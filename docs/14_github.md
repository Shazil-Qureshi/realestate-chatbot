## Terms

| Term | What it is | Why it matters here |
|---|---|---|
| **Git** | A tool that keeps snapshots ("commits") of a project folder. | You can see every change and go back to any earlier version. |
| **Repository** | A folder that Git tracks (it has a hidden `.git` folder). | Created with `git init`. |
| **Commit** | One saved snapshot, with a message and an author. | The author email is public on GitHub, which is why a private address is used. |
| **Remote / push** | The GitHub copy of the repository, and the act of uploading to it. | `origin` is the conventional name for it. |
| **`.gitignore`** | A list of files Git must never pick up. | It keeps the API key, lead data and generated files out. |

## Choices

**Private commit email.** Every commit records an email address, and on a
public repository anyone can read it. Commits use GitHub's private address
(`…+Shazil-Qureshi@users.noreply.github.com`), set for this project only with
`git config`. On GitHub, "Keep my email addresses private" and "Block command
line pushes that expose my email" are both on, so an accidental push with the
real address is refused.

**Public repository.** GitHub Pages (Task 3.4) needs a public repository on
the free plan, and the project is a portfolio piece. That makes the checks
below essential, not optional.

## Problems met

**Files out of date on the laptop.** Before the first commit, the list of files
to be committed was compared, by size, with the build assistant's copies. Four
files on the laptop were older versions: `.gitignore`, `docs/07_ingestion.md`,
`docs/11_leads.md` and `tests/test_chat.py`. Some earlier saves to the laptop
had reported success without changing the file. All four were rewritten and
their sizes re-checked. The newer `test_chat.py` adds a check to CHAT-01, so
CHAT-01 was run again before committing: **1 passed**.

Lesson: confirm a save by reading the result back, not by trusting the
"written" message.

**Push refused (403) for the wrong account.** Windows had a saved GitHub login
for a different work account, and Git used it. Fixed by putting
the username in the remote address, so Git asks for that account's login and
the work login stays untouched:

```powershell
git remote set-url origin https://Shazil-Qureshi@github.com/Shazil-Qureshi/realestate-chatbot.git
```

The owner then approved the sign-in in the browser.

## If a secret is ever committed

Deleting the file in a new commit is **not enough**: it stays in the history.
Revoke the key immediately at its source (AI Studio, Google Cloud), make a new
one, and only then clean the history. A key that has been public, even for a
minute, must be treated as stolen.
